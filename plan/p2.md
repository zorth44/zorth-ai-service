# Tool Calling Foundation

## 1. Change Name

```text
tool-calling-foundation
```

## 2. Goal

在现有 `AI Platform Foundation` 基础上，引入 Spring AI Tool Calling 能力，使 LLM 能够：

1. 理解用户目标；
2. 判断是否需要调用 Tool；
3. 自主选择正确的 Tool；
4. 生成 Tool Arguments；
5. 由 Spring Boot Application 执行 Tool；
6. 将 Tool Result 返回 LLM；
7. LLM 根据结果继续推理；
8. 必要时继续调用其他 Tool；
9. 最终生成回答。

本阶段的核心目标不是实现具体业务 Agent，而是建立并验证：

```text
LLM
 ↓
Tool Selection
 ↓
Tool Execution
 ↓
Tool Result
 ↓
LLM
 ↓
Next Tool / Final Answer
```

即 Agent 最基础的：

```text
Reason → Act → Observe → Reason
```

能力。

提供基础能力。

# 14. ToolContext

本阶段必须实现至少一个 `ToolContext` 示例。

目的：

验证：

```text
Server Context
```

与：

```text
LLM Tool Arguments
```

之间的区别。

例如 Request 进入系统后生成：

```text
requestId
```

通过：

```text
ToolContext
```

传递给 Tool。

概念：

```text
HTTP Request
     │
     ├── message
     │      ↓
     │     LLM
     │
     └── requestId
            ↓
       ToolContext
            ↓
           Tool
```

LLM 应该：

```text
看不到 requestId
```

但 Tool 可以：

```text
获取 requestId
```

---

# 15. ToolContext Example

调用 ChatClient 时：

```text
toolContext
```

包含：

```text
requestId
```

例如：

```java
.toolContext(
    Map.of(
        "requestId",
        requestId
    )
)
```

Tool 可以声明：

```java
ToolContext toolContext
```

并获取：

```text
requestId
```

用于日志。

禁止：

```java
@Tool
public Result someTool(
    String requestId,
    ...
)
```

让 LLM 自己生成 requestId。

# 20. Tool Exception Handling

Tool 可能失败。

例如：

```text
Calculator divide by zero
```

不能导致：

```text
Spring Boot Process Crash
```

需要定义：

```text
ToolExecutionException
```

Tool 层记录：

```text
tool name
requestId
error
duration
```

不得：

```text
吞掉异常
```

也不得把：

```text
完整 StackTrace
内部系统信息
```

直接返回用户。
