# Database Agent 对接问题清单

发给：数据源 / Web SQL 编辑器后端负责人  
来自：AI Platform（`zorth-ai-service`）  
目的：确认 Database Agent 能否改为调用你们的服务，而不是自己直连 JDBC。  
请尽量按题号回答。有接口文档、OpenAPI、示例请求/响应请直接附上。

---

## 背景（给对方看）

AI Platform 已经有一套 Database Agent Tools。模型不会自己拿 JDBC，只会调用这四个能力：

| Tool | 我们现在做什么 |
| --- | --- |
| `listTables` | 按当前数据源列出可查询的表 |
| `getTableSchema` | 取一张或多张表的字段、类型、是否可空、主键、备注 |
| `checkSql` | 执行前校验 SQL；当前策略是只允许单条只读 `SELECT` / `WITH` |
| `executeQuery` | 真正执行查询，并限制行数、超时、结果大小 |

当前实现是 AI 服务自己维护数据源连接并跑 JDBC。你提到数据源和 Web SQL 编辑器已经有后端。两边目前互不知道对方。我们希望：

```text
用户提问
  → AI Platform Agent
  → Database Tools
  → 【你们的服务】
  → 数据库
```

AI 侧继续负责模型、Tool Calling、对用户的回答。  
数据侧继续负责数据源、权限、实际查库。  
`datasourceId` 由我们的调用方传入，不让模型自己编。

## 5. 安全：读写、校验、审计

AI 侧当前硬规则：Agent **只允许只读查询**。即使模型调用 `executeQuery("DELETE ...")` 也必须被拦住。这是我们最关心的边界。

31. 你们执行接口现在允许哪些语句？`SELECT` only，还是 INSERT/UPDATE/DELETE/DDL 都能跑？
32. 有没有现成的 SQL 校验 / SQL Guard？校验发生在执行前还是执行时？用的什么解析器？
33. 如果没有只读模式：能否为 Agent 提供「强制只读」开关（请求参数、专用 API、或数据源账号本身只读）？
34. 只读是靠账号权限、parser 拦截，还是事务 `readOnly`？请说明，避免我们重复做或漏做。
35. 多语句、`SELECT INTO`、存储过程、`CALL`、`COPY`、导出文件这类，现在怎么处理？
36. 查询审计你们记什么？至少我们需要对齐：谁、何时、哪个数据源、哪条 SQL、成功失败、行数。结果集本身我们第一阶段不要求你们落库。
37. 审计日志能否按调用方区分「来自 Web SQL 编辑器」和「来自 AI Agent」？有没有 `client` / `source` 字段可以传？
38. 有没有脱敏、列级权限、行级权限？Agent 拿到的结果是否已经按当前用户过滤？

## 6. 错误形态

    - 表不存在
    - 字段不存在（例如 `Unknown column 'order_time'`）

## 我们暂时不需要你们做的事

除非你认为必须新开 Agent 专用 API，否则第一期请先告诉我：**现有接口能不能覆盖上面四件事**。  
我们不会让模型直连你们的库，也不会在 AI 服务里复制一套数据源账号管理（如果你们已经有的话）。

会话持久化、RAG、表语义搜索、跨数据源 Join、写库 Agent，都不在这次对接范围。
